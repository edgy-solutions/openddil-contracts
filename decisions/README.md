- [ADR-0030: Two-stage configurable ingress — structure vs. semantics](ADR-0030-two-stage-configurable-ingress.md) — Bloblang maps structured data to the Silver ontology; it does not decode binary grammars. Binary wire formats are decoded by format-decoder sidecars driven by declarative format definitions, so adding a format = one definition file + one Bloblang mapping, zero engine code. Stage 1 (grammar) emits raw JSON on `ingress-<format>-raw`; Stage 2 (semantics) is the existing mapping discipline unchanged. Engine policy: definition-driven open decoders where they exist (ASTERIX category XML, hot-loadable), Kaitai Struct otherwise (permissive runtime ships, GPL compiler stays in the build toolchain), JVM-based engines excluded from tactical-tier sidecars as an edge-footprint decision. Controlled-spec formats (tactical datalink) follow the OSS-core/private-overlay split — core ships the sidecar seat + generic Silver shape, the format definition lives in a customer bundle. Ratifies the pattern the DIS path already followed implicitly. **Amended 2026-08-07** for DDS: adds a second ingress class — **middleware participation** — because DDS is a middleware you *join*, not a format you decode (the sidecar is a domain participant doing RTPS discovery and receiving already-typed samples; its definition artifact is `{domain, topics, QoS profiles, type source}` rather than a grammar). Stage 2 and the zero-engine-code claim both survive unchanged, which is evidence the seam was cut at *structure vs. semantics* rather than at bytes. Engine: **Eclipse Cyclone DDS in core** (EPL-2.0/EDL container dependency, no JVM, passes the tactical-footprint discipline); **RTI Connext never ships in OSS** — RTI shops integrate by wire-level DDSI-RTPS interop with the customer overlay carrying their IDL, QoS XML, and DDS Security artifacts. Records the class's characteristic trap as an architectural requirement: **QoS mismatch fails silently** (no match, no data, no error), so discovery/matching state must be a first-class observable — data flow alone is not a health signal. Type handling (IDL-compiled vs. runtime XTypes) left as an explicitly open decision pending honest maturity verification (2026-08-05, Status: Accepted)
- [ADR-0031: Converged edge node — OpenDDIL seams for a co-located reasoning plane (mini-iagent)](ADR-0031-converged-edge-node-reasoning-plane-seams.md) — an OpenDDIL edge can host a co-located reasoning plane (mini-iagent, a reduced deployment of the external Invincible Agent project) that grounds on local logistics truth under the same local policy engine. - [ADR-0032: Tier-local presentation — the reachback finding](ADR-0032-tier-local-presentation-reachback-finding.md) — Arc 1 Phase 0 gate. The finding: all four projectors write to `postgres-hq`, `postgresHq` is the only relational store, and the maintainer UI is served from HQ — so under severance **the persona closest to the equipment has the stalest view of it**, while the data they need flows into a local topic they cannot query. Second inversion: today's severance banners are HQ's view of the edge, not the edge's view of itself. Extends ADR-0022's severance-tolerance invariant from the data plane to the **presentation plane**. Decisions: (a) edges get stores, **regions do not** — structural, not preferential, since a region has no broker of its own and a region-local store would be fed across the very links it exists to survive; (b) identical DDL everywhere, content edge-scoped by construction, keeping ADR-0031's read contract tier-independent; (c) `asset_registry` reaches edges via a compacted `registry-sync` topic — the topology's first deliberate HQ→edge flow, constrained to reference data that enriches but never gates local operation; (d) footprint owned at N node stacks, with bespoke Faust-state reads rejected as a second read-truth; (e) **the edge serves its own UI** (a bundle loaded from HQ cannot load *during* severance); (f) the severance indicator inverts to the edge reporting its own uplink. Arc 1 runs open-access with the Topaz sidecar deployed but deciding nothing (Arc 2's landing zone). Notes plainly that the projector's tier-parameterizability is believed, not proven — Phase 2 exists to falsify it cheaply before helm templating multiplies any gap. **Amended before acceptance** after a framework-level correction: the first draft read this deployment's broker-less intermediate tier as a property of intermediate tiers (it is a Phase-6 shortcut), so the store decision is now a depth-independent conditional rule and the deliverable is the tier-agnostic **tier presentation node** (2026-08-07, Status: Accepted)
- [ADR-0033: The tier hierarchy is unbounded and recursive (framework invariant)](ADR-0033-recursive-tier-hierarchy-framework-invariant.md) — records design intent that had never been written down: every tier is the same self-similar node managing the tier below, rolling up its subtree, passing that rollup to its parent if it has one. **Tier count and names are deployment configuration, not framework structure** — "HQ" is just the node with no parent, "edge" the node whose children are assets, "region" any node with both. A deployment may run edge→region→HQ or edge→region→province→country or add a cross-national tier above that. Node kit `{broker?, aggregator, projector?, store?, presentation?, policy-sidecar?}` with depth-independent dependency rules (severance-tolerant presentation requires that tier's own broker — ADR-0032's discovery, restated at framework scope). Written because ADR-0032's first draft mistook a deployment artifact for design; the defence is a citable document rather than one person's recall. Four constraints bind current work (no tier-kind laws; no new named-tier components; don't deepen the edge_id/region_id assumption; don't assume leaf-stream inputs in new aggregations). Generalization backlog named not resolved: hierarchy-path addressing (assessed for the Arc 1 schema train — **recommend not boarding**, no correctness gate forces it and designing addressing under train pressure is how a regretted shape gets locked in), recursive node templating, broker-bearing intermediate tiers, parameterized presentation, and an ADR-0024 composability audit (unbounded depth is rollup-of-rollups or it is nothing). Arc 1's work is unchanged; Arc 1's claims are corrected (2026-08-07, Status: Accepted)

- [ADR-0034: Tier analytics are deployment configuration, not framework code](ADR-0034-tier-analytics-are-deployment-configuration.md) — the ADR-0033 sequel: that ADR made the *topology* deployment-configurable, this makes the *analytics running on it* configurable. Each tier configures three planes — **collection** (what it takes from below), **aggregation** (what it computes and emits upward), **detection** (algorithmic stream analysis producing events as first-class data, themselves collectable/aggregatable above). All three are hardcoded today; named plainly as the violated invariant. **Investigated finding: detection has a reachback problem too** — `logistics-fusion` renders once in `hub.yaml` (zero times at edge/regional) and subscribes *downward* into every edge broker, so a severed edge gets **no logistics severity computed at all**; same shape as ADR-0032's presentation reachback, one plane over, which makes per-tier detection a DDIL correctness fix and not only a genericity one. Config/code line restated in ADR-0030's idiom: config composes a small verified **primitive algebra** and binds **registered units** (`@register_aggregation` / `@register_detector`, following edge-assignment's `@register_strategy`); algorithms live in code, referenced from config, never expressed in it. Registered units are **parameterized families, not singletons** — otherwise every threshold tweak becomes a registry entry and the registry bloats back into hardcoding. **The audit's classification becomes a type system:** operations are *propagating* (associative — counts, sums, worst-of, mean-via-(mean,count)) or *terminal* (lossy — top-N, percentiles), and the config schema **rejects terminal operations on upward-emitted streams**, making the truncation bug unwritable rather than audited-for; window compatibility is the same check in temporal form. ML units = registered inference wrapper + versioned artifact (ONNX-class) + binding config, distributed over the **same downstream seam** as policy bundles and `registry-sync` (Arc 1 Phase 4 is thus the general artifact-distribution seam, models its third passenger) — inference local, severed tier keeps detecting. Parallelism is a **registration contract** (units declare keying/partitioning; engine refuses unsatisfiable bindings). Mandatory provenance stamps, incl. `model_artifact_hash` for ML events. Two generic wire envelopes (aggregate + typed detection event) so configured analytics never require contracts changes. Records the ML composability tension honestly: **scores are terminal, events are propagating** — score-averaging across tiers is rejected by typing. Engine build, faust rework, fusion migration, coherence validator, and **all of model training/MLOps** explicitly fenced (2026-08-07, Status: Accepted; engine fenced)

## Audits

- [AUDIT-2026-08-07: Aggregation composability (ADR-0024 set)](AUDIT-2026-08-07-aggregation-composability.md) — verifies ADR-0033's unbounded-depth invariant against the three regional rollups. **Result: conditional, not clean.** All three are `assumes-raw-leaves` as implemented, but differ in kind: `region_fleet_summary` (associative counts) and `region_wear_trends` (algebraic mean+count — its wire message already carries the sufficient statistics, so no format change is needed) are plumbing away from composing. **`region_top_factors` is genuinely non-composable**: top-N truncation is lossy, so a factor ranking 6th in every child is emitted by none and is invisible to the parent — silently, compounding with each tier. Fix shapes recorded, none applied. Gate: resolve top-factors before any fourth tier, or any rollup consuming a rollup. Nothing blocks Arc 1. Also carries the label-inventory annotation: **no aggregation's inputs carry releasability labels today** (2026-08-07)
