- [ADR-0032: Tier-local presentation — the reachback finding](ADR-0032-tier-local-presentation-reachback-finding.md) — Arc 1 Phase 0 gate. The finding: all four projectors write to `postgres-hq`, `postgresHq` is the only relational store, and the maintainer UI is served from HQ — so under severance **the persona closest to the equipment has the stalest view of it**, while the data they need flows into a local topic they cannot query. Second inversion: today's severance banners are HQ's view of the edge, not the edge's view of itself. Extends ADR-0022's severance-tolerance invariant from the data plane to the **presentation plane**. Decisions: (a) edges get stores, **regions do not** — structural, not preferential, since a region has no broker of its own and a region-local store would be fed across the very links it exists to survive; (b) identical DDL everywhere, content edge-scoped by construction, keeping ADR-0031's read contract tier-independent; (c) `asset_registry` reaches edges via a compacted `registry-sync` topic — the topology's first deliberate HQ→edge flow, constrained to reference data that enriches but never gates local operation; (d) footprint owned at N node stacks, with bespoke Faust-state reads rejected as a second read-truth; (e) **the edge serves its own UI** (a bundle loaded from HQ cannot load *during* severance); (f) the severance indicator inverts to the edge reporting its own uplink. Arc 1 runs open-access with the Topaz sidecar deployed but deciding nothing (Arc 2's landing zone). Notes plainly that the projector's tier-parameterizability is believed, not proven — Phase 2 exists to falsify it cheaply before helm templating multiplies any gap. **Amended before acceptance** after a framework-level correction: the first draft read this deployment's broker-less intermediate tier as a property of intermediate tiers (it is a Phase-6 shortcut), so the store decision is now a depth-independent conditional rule and the deliverable is the tier-agnostic **tier presentation node** (2026-08-07, Status: Accepted)
- [ADR-0033: The tier hierarchy is unbounded and recursive (framework invariant)](ADR-0033-recursive-tier-hierarchy-framework-invariant.md) — records design intent that had never been written down: every tier is the same self-similar node managing the tier below, rolling up its subtree, passing that rollup to its parent if it has one. **Tier count and names are deployment configuration, not framework structure** — "HQ" is just the node with no parent, "edge" the node whose children are assets, "region" any node with both. A deployment may run edge→region→HQ or edge→region→province→country or add a cross-national tier above that. Node kit `{broker?, aggregator, projector?, store?, presentation?, policy-sidecar?}` with depth-independent dependency rules (severance-tolerant presentation requires that tier's own broker — ADR-0032's discovery, restated at framework scope). Written because ADR-0032's first draft mistook a deployment artifact for design; the defence is a citable document rather than one person's recall. Four constraints bind current work (no tier-kind laws; no new named-tier components; don't deepen the edge_id/region_id assumption; don't assume leaf-stream inputs in new aggregations). Generalization backlog named not resolved: hierarchy-path addressing (assessed for the Arc 1 schema train — **recommend not boarding**, no correctness gate forces it and designing addressing under train pressure is how a regretted shape gets locked in), recursive node templating, broker-bearing intermediate tiers, parameterized presentation, and an ADR-0024 composability audit (unbounded depth is rollup-of-rollups or it is nothing). Arc 1's work is unchanged; Arc 1's claims are corrected. **Amended 2026-08-08** with two framework intents recorded *before* code exists to contradict them: (i) **tier-parameterized presentation** — one UI parameterized by tier showing local truth + subtree rollup, served per node; "the HQ view" is just the root's instance and the current three-view SPA is the **demo instantiation** (legitimate as a demo shell, shipped interim in the node's UI slot), with the forcing function noted — a fourth tier makes *"which of the three views does it get?"* unanswerable; (ii) **lateral peer topology** — the hierarchy is a tree **plus** deployment-configured peer links, a topology-class change, motivated by cross-site inventory query and federated ML (model updates move laterally, raw data never leaves its edge). Four interactions named and fenced: peer exchange is a releasability boundary decided at the **responding** node's local Topaz with no reachback (the per-tier authorizer extends laterally for free); the distribution seam gains a future peer→peer leg; inventory peer-query is a workflow step-type not a feature; and DDIL gets *stronger* since peer links sever independently of uplinks. Fifth do-not-harden constraint added — **nothing may assume strictly-tree data flow**, verified cheap because brokers/projectors/seam are direction-agnostic and only their configuration is tree-shaped (2026-08-07, Status: Accepted)

- [ADR-0034: Tier analytics are deployment configuration, not framework code](ADR-0034-tier-analytics-are-deployment-configuration.md) — the ADR-0033 sequel: that ADR made the *topology* deployment-configurable, this makes the *analytics running on it* configurable. Each tier configures three planes — **collection** (what it takes from below), **aggregation** (what it computes and emits upward), **detection** (algorithmic stream analysis producing events as first-class data, themselves collectable/aggregatable above). All three are hardcoded today; named plainly as the violated invariant. **Investigated finding: detection has a reachback problem too** — `logistics-fusion` renders once in `hub.yaml` (zero times at edge/regional) and subscribes *downward* into every edge broker, so a severed edge gets **no logistics severity computed at all**; same shape as ADR-0032's presentation reachback, one plane over, which makes per-tier detection a DDIL correctness fix and not only a genericity one. Config/code line restated in ADR-0030's idiom: config composes a small verified **primitive algebra** and binds **registered units** (`@register_aggregation` / `@register_detector`, following edge-assignment's `@register_strategy`); algorithms live in code, referenced from config, never expressed in it. Registered units are **parameterized families, not singletons** — otherwise every threshold tweak becomes a registry entry and the registry bloats back into hardcoding. **The audit's classification becomes a type system:** operations are *propagating* (associative — counts, sums, worst-of, mean-via-(mean,count)) or *terminal* (lossy — top-N, percentiles), and the config schema **rejects terminal operations on upward-emitted streams**, making the truncation bug unwritable rather than audited-for; window compatibility is the same check in temporal form. ML units = registered inference wrapper + versioned artifact (ONNX-class) + binding config, distributed over the **same downstream seam** as policy bundles and `registry-sync` (Arc 1 Phase 4 is thus the general artifact-distribution seam, models its third passenger) — inference local, severed tier keeps detecting. Parallelism is a **registration contract** (units declare keying/partitioning; engine refuses unsatisfiable bindings). Mandatory provenance stamps, incl. `model_artifact_hash` for ML events. Two generic wire envelopes (aggregate + typed detection event) so configured analytics never require contracts changes. Records the ML composability tension honestly: **scores are terminal, events are propagating** — score-averaging across tiers is rejected by typing. Engine build, faust rework, fusion migration, coherence validator, and **all of model training/MLOps** explicitly fenced (2026-08-07, Status: Accepted; engine fenced)

- [ADR-0035: Information honesty in operator-facing surfaces](ADR-0035-information-honesty-operator-surfaces.md) — consolidates a rule this project had enforced in six unrelated places without ever writing down: **a surface claims only what its data supports, and where the support differs, the rendering differs.** A value's *basis* is part of the value; two readings with the same pixels and different bases are a defect, not a styling choice. Six claim classes, each with a required distinguishing treatment: **not from the pipeline** (ADR-0017's three markers) vs. the adjacent weaker claim of **modelled-not-measured** (`SYNTHESIZED`, its own third thing rather than rounded to either neighbour); **never observed** (empty states that say *why*, and a not-a-reading sentinel rendered as `—` rather than printed or coerced); **stale, and why** — `assetTier`'s split between `STALE` (*"we expected to hear from it, we didn't"*) and `COMM_LOST` (*"we know why we're not hearing from this"*), same underlying fact, two different things known about it, with recovery hysteresis making the discipline deliberately asymmetric (**quicker to say we have lost something than to say we have it back**); **session-derived** (a browser accumulator never wears the noun of a durable record); **computed elsewhere** (ADR-0032 §f's severance-indicator inversion, generalized: an indicator whose subject is the link between me and someone else is rendered from the local side or not at all); and **no axis's vocabulary borrowed for another** (ADR-0026's collapse argument at the render layer — the CM `DEGRADED` cap). One check, runnable in front of the UI without reading code: *what would have to be true for this pixel to be honest, and does the data establish it?* Explicitly **not** a mandate to decorate everything (if every tile has a badge, no badge is a signal), not a demo-suppression toggle, and not a substitute for fixing the data — **a well-labelled wrong number is still a wrong number.** Six divergences registered rather than written as if true: IH-1 the pre-sync `?? 0` that renders a confident zero produced by having no reading, in the same component whose sentinel handling is otherwise correct; IH-2 **the four CM/ops quadrants are not all rendered distinctly today — three of four are**, pending `OPERATING_WITH_CM_WAIVER`; IH-3 `tactical_events.severity` extracting both a logistics-severity and a configuration-status vocabulary into one unmarked column, so feed filtering crosses two scales that do not compare — class 6 at the *storage* layer, which is why it survived a render-layer sweep; IH-4 "which tier am I looking at" answered by the URL rather than asserted by the surface; **IH-5 the most-derived value in the system carries the weakest provenance** — the mtbf horizon's producer sets neither `confidence` nor `origin`, so it arrives `ORIGIN_UNSPECIFIED`/`0.0`, producer-side; **IH-6 that horizon renders as a bare duration with no basis marker**, the render-side consequence of IH-5 and a class-1 violation, both added 2026-08-12 from AUDIT-2026-08-12 F3/F4 (2026-08-11, Status: Accepted; register extended 2026-08-12)

- [ADR-0036: Failure detectability and degraded-mode behaviour](ADR-0036-failure-detectability-and-degraded-mode.md) — the silent-absence family as a standing position, plus **a register of failure modes with no detection story**, which is the part that is new. Premise: the most expensive defect class here has not been a wrong answer but **a failure that looks exactly like success** — the DDS QoS mismatch that reads as a quiet topic, the site with no feed that reads as a broken deployment, the buffer probe that read `0` on every cluster for months because it queried a consumer group that never existed, the chart header describing two components it never rendered. Each pair is byte-identical from the observer's position, and the buffer case is the sharpest because it made the DDIL buffering claim **unverifiable rather than wrong** — which is worse, since it cannot be argued with. Six clauses: (1) **a probe fails distinguishably from its own zero** — raise on absence with the likely cause named in the message, write a sentinel the consumer cannot mistake for data (`LAG_UNKNOWN = -1`; *a UI showing -1 prompts a question, a UI showing 0 ends one*), warn at WARNING and deduplicated because a signal suppressed by default is not a signal, and keep the genuinely-healthy zero on the ordinary return path so the two stay distinguishable at every hop; (2) absence is never rendered as nominal, stated as an obligation on the *producer* because a sentinel no consumer honours is decoration; (3) fail closed on authorization and labelling, with **label first, enforce second** as a hard completeness gate — and Arc 1's open-access posture stated plainly, since deny-unlabeled is designed, fenced and **not enabled**; (4) **severance is a degraded mode, not an error**, with AUDIT-2026-08-08 as its annex and its scope limits intact; (5) every failure mode carries a one-sentence detection story naming the signal, or it takes a register row — *three lucky finds is not an audit methodology*; (6) **observability is part of the system and inherits its verification burden** — earned from anti-silent-absence machinery that produced a loud failure masking a success for six iterations, the mirror image of the disease it was added to prevent. Register: UD-1 **the severance detector reads a root-tier service, so it depends on the uplink whose loss it detects** — a clause-4 violation inside the mechanism that demonstrates clause 4, with the observed flag flap recorded; UD-2 no tolerance classification has been observed under an actual sever; UD-3 egress and overlay components sit outside every sweep; UD-4 the pre-sync zero, instrument-side; UD-5 middleware-participation health has no observable yet, registered so the sidecar cannot ship without one and call the silence nominal; UD-6 **the register itself is unaudited — the absence of a row is not evidence a component has no undetected failure modes** (2026-08-11, Status: Accepted)

- [ADR-0037: Verification evidence is a deliverable](ADR-0037-verification-evidence-is-a-deliverable.md) — generalizes ADR-0025 past deployment: **a verification claim cites a durable artifact; where no artifact exists, the claim is stated as unverified.** The pattern behind the recurring misses is that *the artifact of a verification is usually a transient* — an exit code, a console summary, a scrollback, a recollection of having looked — so the claim outlives its evidence and by the time someone needs it, it exists only as confidence. Four evidence forms, each with a home and a thing it is competent to prove (finding document · executed procedure · test run · measured pair), and the load-bearing rule that they are **not interchangeable**: a test run cannot prove a deployment, one site's procedure cannot prove a fleet, a source-derived reading cannot prove runtime behaviour. **A claim inherits the competence of its evidence form**, and where it reaches past that, it says so. Seven clauses, including ADR-0025 restated intact; **a guard is not evidence until it has been seen to fail** (green checks that were never red prove nothing, and a check sharing an author and vocabulary with its subject inherits the blind spot — prefer a second check against a *different representation*); assertions against parsed structure, never rendered text; **a rehearsal declares its substitutions** as one document with declared translations rather than two procedures, which is what stops a rehearsal being quietly promoted into the official proof; every investigation states what it did not establish; and findings name an anchor so their tense is recoverable by construction. Seven gaps registered: VE-1 no index of evidence, VE-2 the suite prints and exits 0/1 so *"the suite passed"* cites nothing, VE-3 recordings have a retention policy of "whoever has the file", VE-4 chart self-description checked by hand, VE-5 single-site evidence behind fleet-shaped claims (*structural similarity is a code claim, not a deployment claim*), VE-6 no supersession rule, and **VE-7 — the one gap this ADR creates rather than inherits**: evidence artifacts have no sanitization gate, generalized from three prior instances sharing one shape — **the control describes what it protects** — resolved as *publish the rule, not the pattern list*, with the gate binding **at egress rather than at review**, because a recording cannot be redacted after delivery and an external reader's copy is beyond recall by definition, since being read by someone else is the artifact's purpose. Rejects CI as the single source of verification truth (it cannot produce the deployed-under-severance claims that matter most) and a traceability matrix as primary mechanism (a document parallel to the work drifts from it — ADR-0017's reason) (2026-08-11, Status: Accepted)

- [ADR-0038: Anticipated capability envelope — constraints, not a roadmap](ADR-0038-anticipated-capability-envelope.md) — **the accepted position is the constraint set, not the capabilities.** Written against *foreclosure*, not forgetting: three layers of configurable machinery, each making a locally sensible assumption, collectively making a capability unbuildable without rework — a failure nobody decides on, because the assumption is invisible at the layer that makes it. Follows the ADR-0033/0034 do-not-harden idiom (record the future property as a constraint on present work, verify it costs nothing today), and is written **now** because a configurable layer with users is harder to widen than a hardcoded one. Opens with an **ISO 13374 block mapping** — new analysis, explicitly a reading rather than a conformance claim: blocks 1–3 (acquisition, manipulation, state detection) implemented; **block 4 partial** — the system says *what is wrong*, not *why*, since diagnosis/fault-cause attribution is absent; **block 5 partial in a specific way** — ADR-0020's derivation engine is *built and closed*, so the gap is **mechanism built, prediction absent**: it reports remaining-life *fractions* against authored coefficients, not a *horizon with an uncertainty band*, and a horizon implies a validity claim unvalidated coefficients cannot support; **block 6 (advisory generation) absent**; presentation implemented; external interfaces implemented **reference-only** — `work_order_ref` points at an externally created order, the system never originates one. Carries a **standing boundary clause**: operational COA generation and analysis are permanently outside the boundary — *an architectural limit, not "not yet"* — on two grounds, adoptability (a logistics system that starts evaluating schemes of manoeuvre competes with the staff process it should feed) and a **safety-bar step-change** from decision-support to decision-assertion, which is a different hazard class rather than a larger one. Stated here rather than only in ADR-0011 because a configurable analytics plane plus a configurable process plane is exactly the machinery that could drift across that line **without anyone deciding to**. Three anticipated capabilities, each with what-it-is / what-it-is-not / substrate-composed / constraints / trigger: **CBM completion** (prognostic horizon + advisory generation); **sustainment feasibility analysis** — *can a proposed operation be supported* — whose defining gap is that **no demand model exists anywhere**, named and **deliberately not designed** (premature abstraction is the failure this series has repeatedly avoided); and **advisory provenance**, separated out because it is the cheapest thing on the list to foreclose and the only one whose trigger is a precondition rather than a demand signal — a wrong detection produces a misleading display, a wrong advisory produces an action. Seven binding constraints (C1 envelope must carry recommendation/horizon/uncertainty · C2 registry output vocabulary stays open · C3 analytics inputs not typed observed-state-only · C4 advisory provenance not inheriting the detection stamp by default — **the one with a clock on it** · C5 workflow subject not assumed to be an asset · C6 feasibility over rollups is rollup-of-rollups so GD-05's gate binds · C7 nothing may assert a course of action is supportable), each with its cost today stated. Registered gaps: **AE-1 — ADR-0011 claimed "dynamic work order generation" and nothing generates work orders**, with the contract shape pointing the opposite way — the corpus's first claims-vs-sources defect at the ADR layer, **RESOLVED 2026-08-12**: ADR-0011 amended to state work-order *correlation*, the claim relocated to §3 as anticipated with a propose/dispose boundary, row kept because the record of what was claimed is the useful part; **AE-2 — the only recommendation-shaped field is `ManualDiscrepancyRaised.recommended_action`, a bare human-authored string**, which is the natural attractor for the first machine advisory and would give machine advice the provenance profile of a free-text note; AE-3 supply-only; AE-4 fraction-not-horizon; AE-5 GD-10 is a prerequisite here too; AE-6 diagnosis absent and deliberately not on the list. Ends with a did-not-establish section (ADR-0037 clause 6 applied to itself) — **no sweep for existing foreclosure was run**, so the absence of a violation is not evidence of none (2026-08-12, Status: Accepted; capabilities anticipated, not committed)

- [ADR-0039: The bridging thesis — tactical and sustainment planes](ADR-0039-bridging-tactical-and-sustainment-planes.md) — **positioning; nothing built.** Becomes the primary answer to *what is OpenDDIL for*, superseding ADR-0011 in that role (which stays valid on its narrower strategic-tools question and is amended to point here). The premise: tactical systems model the fight, materiel systems model the stock, they were built by different communities decades apart, and **a track number and a stock record can describe the same rounds and share no vocabulary**. Neither model is wrong — **nobody owns the correlation**, so the logistics picture in an operations centre is frequently maintained by hand, which is where readiness actually lives and is the least durable artifact in the room. Compounded by a class characteristic stated generically: materiel management in this domain is increasingly **cloud-resident** (excellent for a garrison, poor for a forward site) and commonly replicates by **row state**, resolving collisions by value precedence without reference to intent — so offline operation is fragile and genuine business conflicts surface as **manual reconciliation at the database layer**. Position: **OpenDDIL is the correlation layer — owns neither plane, speaks both, preserves each side's provenance**, because readiness lives in the intersection and is fully represented in neither. Three commitments: (1) **correlate, do not transact** — the `work_order_ref` precedent generalized from maintenance to supply, because a correlation layer that transacts becomes a second system of record for the same objects, which is the condition producing the problem it exists to relieve; (2) **preserve both provenances** rather than fusing them, since a correlation that discards its inputs' lineage is exactly as unexplainable as an unstamped derived value; (3) supplies the **structural argument ADR-0038 §2's COA fence was missing** — correlation and evaluation are different acts, a neutral join is adoptable by both communities *precisely because it asserts nothing either would dispute*, and a layer that starts scoring becomes a third opinion unadoptable by both. **The neutrality is the product**, so the fence is principled rather than scope-avoidance. Also records the rationale that was missing for two early enterprise integrations — they were the first instances of this seam, scoped before the framing existed to explain them, which is why they read as customer plumbing and got deprioritized. **What is actually there was read, not assumed:** one demo saga step POSTing a hardcoded payload to a work-orders endpoint on a hostname present in no compose file and no chart, documented by the project's own tests as dead and never exercised — **egress-only, one-shot, fire-and-forget**, plus naming and intent elsewhere. Honest summary: *an aspiration with a stub, not an integration pattern* — better than a half-built coupling because nothing must be undone. Did-not-establish: how those systems actually behave, their cadence and identifier schemes, and whether the earlier scoping was ever meant to be bidirectional are **unverified from this repository** and must precede planning rather than follow it (2026-08-15, Status: Accepted; positioning, nothing built)

- [ADR-0040: Offline sustainment operation and intent-based reconciliation](ADR-0040-offline-sustainment-and-intent-reconciliation.md) — **design position; nothing built.** The sustainment side of ADR-0039's bridge has a property the tactical side does not: its authoritative systems are frequently unreachable from the sites that most need them, so **the disconnection is survivable and the reconnection is not**. Seven decisions. (1) **The read side is already solved** — cached materiel state is the **sixth passenger** on the HQ→tier distribution seam after policy bundles, `registry-sync`, ML artifacts, workflow definitions and CM baselines, inheriting stale-but-present, never-gates-local-operation, age-rendered-honestly; a seam that keeps acquiring passengers it was not designed for is evidence it was cut in the right place. (2) **The write side is new and does not compose existing planes** — recorded as an explicit exception to ADR-0038's claim that every anticipated capability does, since a locally-originated write destined for a remote authority is neither an observation nor distributed reference data. (3) **Provisional state is a first-class claim**: a locally-raised action is intent the system of record has never seen and may reject, rendering as `asserted-locally-unconfirmed` (neither measured nor derived) and **never as an accepted transaction** — with **three** states not two, because a rejected intent that silently disappears is worse than one never raised. (4) **Replicate intent, not state** — the load-bearing decision: row replication resolves by precedence and **discards the meaning behind both writes**, so every genuine disagreement arrives as a mechanical collision a human reconstructs intent from at the database layer hours later; intent replayed against authoritative state makes most apparent conflicts **evaporate rather than resolve** (two sites each consuming three rounds from ten are *commutative, not conflicting*) and turns the remainder into **named business exceptions with intent attached**, routable to a supply role rather than to whoever has database access. (5) Actions typed **freely-mergeable / order-dependent / exclusive** — deliberately ADR-0034's propagating-vs-terminal typing applied to writes, making the unmergeable case unrepresentable rather than audited-for; **the taxonomy is named as real work and not designed here**. (6) Every intent carries **its cached basis** — *"raised against a stock reading 6 hours old"* — which is what makes an exception diagnosable and exonerating rather than merely reported. (7) **The boundary under stress**: while severed OpenDDIL is the only place the intent exists, which resembles being the system of record — the line is *"holds intent durably and authoritatively **as intent**; never holds the transaction"*, local authority over what happened here, central authority over the record. Two limits registered: **the operations intent replay requires are a declared contract integrators build toward, not a precondition to be discovered** — an integrator adopting OpenDDIL owns their materiel system and will build an interface *because* they are integrating, so the interface is a deliverable of the integration rather than a constraint on it; OpenDDIL therefore **declares** the verbs (*consume*, *requisition*, *record maintenance*, …) and the reconciliation semantics survive the integration instead of being lost at a boundary someone else shaped, with the contract kept **modest** since a large contract is a large adoption barrier, and a system that genuinely cannot expose operations recorded as an explicitly-labelled **degraded mode** (keep intent locally, accept row semantics, lose the conflict-evaporation property) rather than as the case that sets everyone's ceiling — and **reconciliation outcomes persist on the intent permanently**, not discarded on success, since *raised → accepted* is the only evidence the offline path worked (2026-08-15, Status: Accepted; design position, nothing built)

- [ADR-0041: Ontology convergence across streaming and warehouse ecosystems](ADR-0041-ontology-convergence-streaming-and-warehouse.md) — **design position; nothing built.** Why ADR-0039's correlation **is not a matching problem and cannot be solved by better matching**: a heuristic join would be *probably* right, unexplainable when wrong, and correctly rejected by both communities. What makes a join defensible is a **declared model both sides map onto** — the same disease as GD-10 (payload shape undeclared), GD-11 (class inferred from publishing behaviour) and GD-12 (absence conventions known only to consumers), now at portfolio scale: **absent a declaration, meaning is set de facto by whoever integrated first.** The convergence: a **metadata catalog names the lowest-layer shapes**, standard maintenance/materiel ontologies map onto those, and **each ecosystem translates with the mechanism native to its medium** (stream mapping for wire formats, extraction and warehouse-transform tooling for record systems) — **one declared model, many transport-appropriate mappings, not one transformation language forced across every medium**, because forcing uniformity at the transformation layer is what makes practitioners route around a canonical model and decanonicalise it. This is ADR-0030's structure-vs-semantics split restated one level up, and *the same seam working at two scales is evidence it is cut at the right joint*. **OpenDDIL's Silver model becomes a published shape in that catalog**, which is the precondition for correlation being declarative rather than bespoke — today it is authoritative inside the project and invisible outside it, so any correlation would reverse-engineer it (GD-10 one layer up). Sibling projects named as capability classes only. **Two asymmetries, both unsolved, both binding:** (a) **cadence** — streaming state is continuous/latest-wins/tier-local/severance-tolerant while record-system state is transactional/point-in-time/reachable-only-when-connected, so **every correlated value carries two timestamps and two authorities** and a naive join emits a value whose freshness is silently that of its stalest input while presenting as current; join semantics across differing cadences is new work and *a correlation must not present a fused freshness*; (b) **direction** — streams push, record systems are queried, so the layer must decide when to ask, cache, and be honest about cache age at every tier including severed ones — `registry-sync` is the shape that solves this, which is ADR-0040 §1's observation arriving from the ontology side. Closes with a **portability requirement**: the honesty rules must travel **with the framework**, not stay in one project's PRINCIPLES file, because a configurable mapping ecosystem multiplies the surfaces where cheap inference fills a vacuum — declared-not-inferred, absence must be expressible, fallbacks refuse rather than answer, provenance on every derived value. Did-not-establish: which standard ontologies, **which identifiers actually correlate** (the central practical question, untouched), the catalog's technology and governance, the sibling projects' current state, both asymmetries, and — stated plainly — **the portability requirement has no mechanism, and a rule with no mechanism is a hope** (2026-08-15, Status: Accepted; design position, nothing built)
